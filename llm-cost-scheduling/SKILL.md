# 按计费时段省钱 + 答末标注峰谷

## When to Use

- 用户问 API 花销、要省钱、要决定「重活/批量活/cron 排到什么时候」。
- 要报当前是峰时还是谷时(本用户把它作为**每条回答的固定尾部**,见下)。
- 换主力模型后要重新算「现在跑贵不贵」。

## 硬规矩:仅走 DeepSeek 官方直连时,答末标注计费时段(陛定 2026-11-12 修订)

**只在请求打到 `api.deepseek.com`(provider=deepseek)时**,才在回答结尾带一行时段标签。

**走中转池一律不加**(Agent2API `192.168.50.1:3065`、CLIProxyAPI `50.1:8317`、nvidia 等):池子按 credits 倍数
计费,不受 DeepSeek 峰谷规则约束,照着加反而误导。判断当前会话走哪边:

```bash
grep 'OpenAI client created (agent_init' ~/AppData/Local/hermes/logs/agent.log | tail -3
# provider=custom base_url=http://192.168.50.1:3065/v1 -> 池子,不加
# provider=deepseek base_url=https://api.deepseek.com/v1 -> 官方,加
```

官方直连时的做法:

```bash
python D:/hermes-test/bin/dspeaktag.py     # 现算,不许凭记忆或看时钟猜
```

输出形如 `17:16 波谷 ¥1/¥4 每百万(周末全天·峰价半) · 下次峰时 11-09(周一) 09:00`,原样贴在回答最后一行。

- **谷时那行必须写清「为什么是谷时」+ 切换点带星期**。只给一个时间点(`11-09 09:00 转峰时`)
  会被读成「现在已经是峰时」——用户当场会问「今天不是周六吗？」。周末写 `(周末全天·峰价半)`,
  工作日午间/夜间写 `(非峰时段·峰价半)`;切换点一律 `MM-DD(周X) HH:MM`。别为 shorten 改回旧短版。

- **必须跑脚本算**:时间、星期、跨日切换点都由脚本给,自己心算必错。
- 本 skill 的 `scripts/dspeaktag.py` 是权威副本;`D:/hermes-test/bin/` 那份被清理时从 `scripts/` 重新落一份。
- 长回答也只加一行,别展开解释规则 —— 用户要的是状态,不是教材。
- **会话中途才拿到本技能时,从当前这条回复起立即生效**:先 `skill_view` 本技能 + 跑一次 `dspeaktag.py`,这条回复就带上标签。**绝不能回“需要重开对话才生效”** —— 这是错的,也是用户最不想听的解释。
- 用户会直接质问「说好的每句标峰谷呢」:这就是“漏标”的信号。除了从本条起补上,还要把这条常驻规矩写进记忆(记忆满时先在同一批次里压缩/删除旧条目腾位,再 add)。

## 官方规则(api-docs.deepseek.com/quick_start/pricing)

| | 北京时间 | 价格(每 1M tokens) |
|---|---|---|
| **峰时** | 周一至周五(不含中国法定节假日)**09:00–12:00、14:00–18:00** | 谷时的 2 倍 |
| **谷时** | 其余全部 —— 含工作日 12:00–14:00 午间、18:00–次日 09:00、**周末与节假日全天** | 一半 |

| 模型 | 输入(缓存未命中) | 输入(缓存命中) | 输出 |
|---|---|---|---|
| deepseek-flash | 谷 ¥1 / 峰 ¥2 | 谷 ¥0.02 / 峰 ¥0.04 | 谷 ¥4 / 峰 ¥8 |
| deepseek-v4-pro | 谷 ¥4.5 / 峰 ¥9 | 谷 ¥0.15 / 峰 ¥0.3 | 谷 ¥13.5 / 峰 ¥27 |

一天 24 小时里 17 小时是谷时 —— 「贵」只贵在工作日上下午两段。

## 排期怎么做才真省

1. **能挪的都挪到谷时**:批量转写/整理/大文件分析、一次性重建、cron 定时作业,排到
   **工作日 12:00–14:00 午休档**、**18:00 之后**、或周末全天。即时对话挪不动,不用纠结。
2. **cron 的时间点本身就是成本决策**:新建作业先问一句「这个点落在峰时吗」。
   `*/30 * * * *` 这种全天候作业,峰时那 5 小时要付双倍 —— 能改成 `12,18-8` 窗口就改。
3. **缓存命中比时段更值钱**:命中价约为未命中的 1/50~1/30,长 system prompt + 稳定前缀的收益远大于错峰。
   要省钱先看 prefix 是否稳定,再谈时段。
4. **重模型(v4-pro)费率是 flash 的 3~4.5 倍**:能 flash 完成的活别用 pro 抠细节;
   另外 pro **不支持识图**,带图任务本来就得走 flash。
5. 用户提「最近只能用 DeepSeek,鉴于费用节省」这类前提时,**结论要落到可执行排期**
   (哪类活挪到哪个窗口),不要只背价格表。

## 坑

- **旧规则 `16:30–00:30 UTC 打五折` 早已作废** —— 那是 V3/R1 时代(deepseek-chat / deepseek-reasoner)的
  错峰优惠,随旧模型一起下线。网上大量教程仍在传,照抄会把峰谷判反。以官方 pricing 页为准。
- **峰时是「翻倍」不是「上浮」**:谷价×2 = 峰价;写「便宜 30%」之类的描述都是错的。
- **工作日午休 12:00–14:00 是谷时**,很多人以为白天全是峰时,白白放弃最方便的重活窗口。
- **节假日:API 按中国法定节假日全天算谷时**,脚本只认周末 —— 长假期间给出的「下一波峰」可能偏早,
  回答里点一句「节假日全天算谷时」即可,别硬算日历。
- **标签的歧义会变成信任问题**:用户追问「今天不是周六吗,怎么还有峰时」说明标签被误读了,
  不是用户看错。修的是输出措辞(写明谷时原因 + 切换点星期),不是在回答里另起一段解释规则。
- **计费时段按服务端接收到请求的时刻判定**,一次请求跨时段不重算;所以「赶在 17:59 发出去」和
  「18:01 才发」是两倍差价,长任务尤其值得卡点。
- 别拿「面板/客户端显示」推断账单:只认 `/usage` 级的 token 数与这条时段规则。
